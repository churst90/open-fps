Cody (2026-09-24): "do not use mannered pros in these documents." readme = overview of what OpenFPS
is, its strengths and features; todo = planned work in a structured, clear priority order; changes =
the content of the recent commits; a user manual (client and server).
**Why:** these are for users and for planning, not essays; the code comments' narrative style does
not belong in them.
**How to apply:** short plain sentences, headings and lists, no flourishes or storytelling.
